## 2. Структура 16 осей по изображению [P, PDF стр. 11]

| Технологическая группа (название в PDF) | Оси | Количество | Что можно утверждать |
|---|---|---:|---|
| Positioning | D, D2, U3 | 3 | Позиционирование |
| Feeding | U | 1 | Подача |
| Downward Rotation | C | 1 | Вращение вниз (термин каталога) |
| Up rotation | C2 | 1 | Вращение вверх (термин каталога) |
| Clamping | H3 | 1 | Зажим |
| Pressing | Z1, Z2, Z3 | 3 | Прижимное движение |
| Yielding | X1, X2, X3 | 3 | Отвод / уступание |
| Bending | Y1, Y2, Y3 | 3 | Гибочное движение |
| **ИТОГО** | | **16** | |

**Важно:** PDF показывает группы функций и направление стрелок, но не содержит таблицы механических ходов, нулевых координат, скоростей, ускорений, приводных связей, способа синхронизации Y1–Y3 или X1–X3. Не считать Y1–Y3 тремя независимыми ножами; для этого нет подтверждения. Аналогично, не считать C и C2 двумя последовательными вращениями одного листа без уточнения конструкции.

## 3. Технологическая модель для симуляции (гипотеза, а не заводской цикл)

1. **POSITION:** проверить захват/ориентацию, позиционировать лист группой D/D2/U3.
2. **FEED:** переместить заготовку по U до линии конкретного гиба, поддерживать геометрическую привязку к внешней кромке.
3. **CLAMP:** закрыть зажим H3 и прижим Z1/Z2/Z3; запретить свободный поворот и подачу удерживаемой детали.
4. **APPROACH:** вывести гибочный узел из исходного положения посредством согласованных X/Y.
5. **BEND:** интерполировать движение гибочного узла по двум координатам X и Y с учётом фактической геометрии ножа, листа и контакта. При заданном состоянии верхнего/нижнего ножа контролировать контакт и запрещать сквозное пересечение.
6. **RETRACT:** отвести нож с учётом уже согнутой полки.
7. **UNCLAMP:** раскрыть прижим, выполнить проверку безопасности перед подачей.
8. **NEXT:** при следующем гибе той же стороны подать лист по U; при переходе стороны выполнить безопасное размыкание/отвод, вращение механизмами C/C2 только в подтверждённом режиме, затем новую подачу.

**Порядок гибов:** внешняя линия на одной стороне → следующая внутренняя линия, как описывает Prima Power [S2]; наш согласованный пример: сначала гиб 20 мм у свободного края, затем гиб 100 мм ближе к дну. В программе должны совпадать номер гиба, реальная линия, профиль, перемещение U и отображаемая анимация.

Это последовательность состояний, пригодная для обучения. Реальное перекрытие операций при 16-осевой одновременной интерполяции, включая то, какие оси движутся одновременно, определяется только машинными циклограммами/инструкцией.

## 4. Геометрия движения и необходимые физические проверки

- Модель листа: L×W, t, предел прочности/тип материала, припуски на гиб, нейтральный слой, углы, направление, число полок и стороны.
- Линии гибов должны отсчитываться от свободного края к дну; развитая длина включает припуски по каждому изгибу.
- Прижим и неподвижная опора задают базовую линию гиба; во время активного гиба положение удерживаемого дна условно неподвижно.
- Контакт ножа с наружной поверхностью и упруго-пластическая деформация сложнее идеальной касательной к окружностям. Модель движения по кругу радиуса `Rнаруж+Rнож` — **схематичная геометрическая гипотеза**, а не реальный закон X(t), Y(t).
- Для каждого временного шага проверять пересечение объёмов: лист/прижим, лист/стол, лист/верхний и нижний нож, лист/захват, лист/рама, инструмент/инструмент; проверять также интервалы между шагами, иначе возможен пропуск столкновения.
- Реальная компенсация пружинения зависит от материала, толщины, направления прокатки, радиуса и нагрузки и требует экспериментальной калибровки.
- Реальная корректировка положения X1–X3, Y1–Y3, Z1–Z3 при прогибе балки не выведена из PDF и не должна симулироваться как проверенный закон.
- Профили прижимного инструмента, монолитного стола и R2 ножей в существующем симуляторе частично восстанавливались по другим эскизам; их нельзя считать подтверждённым точным 3D-чертежом станка.

## 5. Аудит текущего проекта `index.html` (GitHub main, состояние на 10.11.2026)

**Обнаруженные пробелы:**
- `limits={steel:2,inox:1.5,aluminum:2.5}`, `defs.maxWidth=1250` — несоответствие PDF-профилю 3/2/3,5 и ширине 1500 мм. В будущем добавить явный селектор профиля машины вместо скрытой замены данных.
- `partPose()` описывает упрощённые поворот/подачу листа как общий поворот и сдвиг без полного независимого состояния 16 осей.
- `cycleProgram()` создаёт условные стадии `position / turn / feed / clamp / bend / release / retract`, не список осевых команд.
- `benderGeometry()` применяет геометрический `bendContact()` и не рассчитывает фактические перемещения X1–X3/Y1–Y3.
- `clampGap()` управляет одним обобщённым раскрытием, не тремя независимыми Z.
- 0,2 с/гиб в паспорте — верхняя заявленная производительность отдельного гиба; коэффициент времени анимации `tick()` выбран для визуализации, не измерен по заводскому циклу.

**Что нельзя делать без дополнительных данных:** назначать физические ходы и ускорения осям, экспортировать траекторию в ЧПУ, утверждать реальную технологичность детали и полную защиту от столкновений.

## 6. Требования к следующему этапу разработки

**Этап А — цифровой двойник осей для обучения:** декларативная таблица всех 16 осей с полями `axisId, group, direction, unit, actualPosition, targetPosition, state, knownLimits`; показать движущиеся узлы разными цветами и отдельно включать/выключать их. Неподтверждённые пределы отмечать как unknown, а не 0 или фиктивным значением.

**Этап B — машинные состояния:** построить дискретную циклограмму и кинематический граф узлов `stock/feeder/rotator/clamp/table/benderFrame/upperBlade/lowerBlade`; запретить опасные переходы при активном зажиме и без безопасного отвода. Установить связь с таймлайном и текстовой программой.

**Этап C — параметрический решатель:** на основе калиброванных контуров и заводских схем вычислять X/Y/Z, состояние C/C2, контактные пары, углы листа и технологические допуски. Применять интерполяцию только между физически допустимыми положениями.

**Этап D — верификация:** тесты на двух гибах одной стороны (20 затем 100 мм), четырёх сторонах, смене направления вверх/вниз, двойных полках, углах, отводе/повороте, граничной толщине, пружинении и сохранении JSON. Сравнить хотя бы одну траекторию с видео/телеметрией именно BDC3200; до сравнения отмечать «приближённо».

## 7. Какие заводские материалы нужны для точности

1. Руководство по эксплуатации BDC3200 с обозначениями осей, положительными направлениями, референсами и ограничениями.
2. Схема привязки серводвигателей к приводам и кинематическая схема X/Y/Z/D/U/C/H3.
3. Параметры системы ЧПУ/циклограммы для простого гиба вверх, вниз и поворота стороны (без конфиденциальных паролей/ключей).
4. Размерные 2D-профили ножей, прижимов, столов, позиционеров и узлов вращения.
5. Короткие референсные видео узлов в боковой проекции с указанием угла и толщины листа для сопоставления траекторий.

**Итог:** документация позволяет достоверно смоделировать функциональные группы и стадии 16-осевого станка, но пока недостаточна для полного физически точного движения отдельных осей.
